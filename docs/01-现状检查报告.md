### 2.4 代理——根因已定位（影响全部命令行工具）

**现象**：`pip install` 与 `curl` 全部卡住 15 秒 ×5 次重试后失败，报
`ConnectTimeoutError(host='127.0.0.1', port=8522)`。

**根因**（三层，逐层排除后确认）：

1. WorkBuddy 宿主会向**每个子进程**注入 `HTTP_PROXY` / `HTTPS_PROXY` 指向 `127.0.0.1:<随机端口>`（本轮先后观测到 **8522** 与 **7231**）。
2. 该端口**没有服务在监听** —— 实测 `</dev/tcp/127.0.0.1/7231` → `CLOSED`。
3. 用户注册表里配置的 Clash 端口 `127.0.0.1:7897` 同时 `ProxyEnable = 0`（未启用）。

→ 三者叠加的结果：所有遵循环境代理的工具（pip、curl、git HTTPS）**必然超时**，且与网络好坏无关。

**验证与修复**（已实测有效）：

```bash
# 绕过：清掉代理变量
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy NO_PROXY='*' \
  .venv/Scripts/python -m pip install -e ".[dev]"
```

项目内所有脚本（`preflight.py` / `bootstrap_remote.py`）已内置「显式忽略代理」的 opener，
不受此问题影响；需要走代理时用 `--proxy http://127.0.0.1:7897` 显式指定。

`docs/03` 第五节已核对官方文档，Free 账号下**私有仓库会关掉三条通道**：

| 通道 | Free + 公开 | Free + 私有 |
