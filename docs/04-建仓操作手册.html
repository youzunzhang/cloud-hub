它不是投资/持仓建仓，也不是聊天群里的「建群」。

一、你必须做的 6 步

  1. 打开 GitHub 并确认已登录
    在哪
    浏览器地址栏输入 github.com
    会看到
    已登录：右上角出现你的圆形头像；未登录：右上角是 Sign in 按钮，点它登录
    提示
    若页面打不开或转圈很久，说明本机网络到 github.com 不稳（我实测过：这台机器直连会超时）。这时打开你平时用的代理/VPN 再试，或换手机热点
  2. 点右上角的「+」，选 New repository
    在哪
    页面右上角，头像左边有一个 + 号 → 在下拉菜单里点 New repository
    捷径
    也可以直接在地址栏打开 https://github.com/new，效果一样
    会看到
    跳转到标题为 Create a new repository 的表单页
  3. 填仓库名（这一步只有两个空要填）
    Owner
    保持 youzunzhang 不动（下拉框默认就是你）
    Repository name
    填 cloud-hub　只能是英文字母、数字和 . - _，不超过 100 个字符
    Description
    选填，可粘贴：以 GitHub 为云端的任务执行与交付基础框架
    会看到
    名字输入框下方出现绿色对勾「cloud-hub is available」代表名字可用
  4. 选可见性：Private 或 Public（这里要做个选择）
    在哪
    表单中间「Choose a repository visibility」下的两个圆点
    怎么选
    Private（私有，只有你能看）：安全，但 Pages 网页托管和分支保护在免费账号下用不了
    Public（公开，任何人可看）：代码会公开，但 Pages、Actions 分钟数、分支保护、安全扫描全部免费且不限量
    我的建议
    这个项目里没有隐私数据、只有框架代码 → 选 Public 最省事，四条通道全开。若你打算往里放个人数据，就选 Private，Pages 暂时不用
    为什么这次要你亲自选 上一轮我默认给了 Private，但核对官方文档后发现：GitHub Free 计划下，私有仓库不支持 Pages， 也不支持分支保护与代码扫描。所以「私有 + 免费」= 我配的三条通道里会有三条失效。
  5. 下方三个勾选框，一个都不要勾
    在哪
    「Initialize this repository with:」下面的 Add a README file、Add .gitignore、Choose a license
    为什么
    因为你电脑上已经有这些文件了。GitHub 官方文档原文：“If you're importing an existing repository to GitHub, don't choose any of these options, as you may introduce a merge conflict.”（导入已有仓库时不要勾，否则会产生合并冲突）
    会看到
    三个框都是空的，页面底部绿色按钮 Create repository 可点
  6. 点绿色按钮 Create repository
    在哪
    表单最下方绿色按钮 Create repository
    会看到
    跳到一个叫 Quick setup 的页面，上面写着 git remote add origin … 的命令。这些命令不用你执行，我这边已经配好了
    然后
    回来跟我说一句「建好了」，剩下的推送、开 Pages、跑流水线我来做
如果你想少点几下：URL 预填（官方支持） 打开这个链接，名字和可见性会自动填好，你只需确认三个框没勾、点 Create：
https://github.com/new?name=cloud-hub&visibility=public&owner=@me
想把默认值换成私有，把 public 改成 private 即可。 来源：GitHub Docs「Creating a new repository → Creating a new repository from a URL query」，2026-10-25 核对。官方列出的参数为 name / description / visibility / owner / template_owner / template_name。

四、可能过时 / 容易踩的坑（附替代方案）

1. 网上老教程里的 git branch -M main

那是 2020 年前后默认分支叫 master 时代的写法。现在新建仓库默认就是 main，本仓库也已用 git init -b main 建好，不需要再执行。

2. GitHub 界面文字会改版

如果某天你看到的按钮不叫 New repository 了，按语义找：右上角 + 号里的第一组，或直接访问 https://github.com/new。设置页同理——只要记住左侧栏分组「Code, planning, and automation」下面依次是 Branches / Pages / Actions。

3. 「私有 + 免费」的三条失效通道，替代方案如下

失效的免费替代方案
Pages 网页托管① 改公开仓库；② 用 Release 附件下载 HTML 单文件在本地打开；③ 升级 GitHub Pro
分支保护 / Rulesets① 本地 pre-commit 钩子（已配好）拦下不合格提交；② CI 失败即视为不可合并，靠自觉；③ 改公开仓库
CodeQL 代码扫描① 公开仓库直接可用；② 改在 CI 里跑 ruff + pip-audit（免费、无需 GHAS）；③ 暂不开启

4. Actions 定时任务的两条官方限制（我在工作流里已注释）

  • cron 不准点：高负载时 GitHub 会延迟甚至丢弃定时任务，所以对「准点」有要求的场景要用外部定时器触发 workflow_dispatch。
  • 60 天无提交会自动停用 schedule 工作流，需要手动 Enable。

5. 安全提示：Pages 是公开的

官方原话：“GitHub Pages sites are publicly available on the internet, even if the repository for the site is private”。所以不要把任何密码、密钥、个人数据放进 site/ 目录。
